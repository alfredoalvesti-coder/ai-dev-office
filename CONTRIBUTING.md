# Como contribuir

O projeto está na fundação. Consulte o roadmap e alinhe a Issue antes de ampliar o escopo. A licença será definida pelo titular antes da publicação pública. Contribuições externas dependem dessa definição.

1. Abra uma Issue com problema, fase, critérios de aceite, dependências e testes propostos.
2. Crie uma branch curta por mudança, como `feat/project-registration`.
3. Implemente comportamento simples e testes que verifiquem contratos e falhas.
4. Execute os testes e builds descritos no README. Use Docker para validar PostgreSQL real.
5. Abra um PR usando o template, incluindo evidências e limitações do ambiente.

Mensagens de commit podem seguir Conventional Commits. Evite mudanças de formatação em arquivos sem relação com a entrega. Revisões devem avaliar responsabilidade dos módulos, consistência transacional, validação, segurança e legibilidade.

Encontrou um segredo? Não publique o valor em Issues ou logs. Remova a exposição e combine a rotação pelo canal apropriado antes de tornar o histórico público.
